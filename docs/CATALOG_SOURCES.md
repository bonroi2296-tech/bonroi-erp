# 제품 카탈로그 데이터 소스 조사

> 사진·박스당 수량·EDI 등 제품 정보를 어디서 어떻게 채울지 정리.
> 결정·실행 상태는 PROJECT_CONTEXT.md 의 "다음 할 일" 과 동기화.

## 결론 한 줄
**C(공공 API)를 메인 베이스로 깔고, A(명세서 누적/촬영)로 사진·박스수량을 보완, B(스크래핑)는 보조.** B는 봇 차단 때문에 비용 대비 효율 낮음(아래 4번 참조).

## 1) 데이터 항목별 메인 소스
| 항목 | 메인 | 보조 |
|---|---|---|
| 제품명·등급·제조사·UDI-DI·EDI(보험)코드 | **C 식약처 UDI/EDI 통합** | B |
| 가격(상한단가)·규격·급여구분 | **C HIRA 치료재료정보** | B |
| 사진 | **A 우리 촬영/요청** | B(있으면 다운로드) |
| 박스당 수량·단위 | **A 명세서 AI 학습**(현재 출고확인서 반영 시 자동) | B |
| 짧은 설명·용도 | **C/B → 수동 보정 A** | — |

## 2) C — 식약처(MFDS)
### 2-1) 의료기기 UDI/EDI 정보 조회 서비스 (가장 중요)
- 공공데이터포털: https://www.data.go.kr/data/15138675/openapi.do
- 제공: 의료기기 소분류 품목명, 등급, 제조·수입 업체명, 제품명, 품목허가번호, 모델명, **UDI-DI 코드**, 요양급여 대상 치료재료 여부, **요양급여(EDI) 대상 치료재료 코드**
- ⇒ 우리가 쓰는 "EDI 코드"가 보험 EDI라면 여기서 매칭 가능.

### 2-2) 의료기기 표준코드별 통합정보
- 공공데이터포털: https://www.data.go.kr/data/15073863/openapi.do
- 제공: UDI-DI, 라텍스/프탈레이트 포함 여부, MRI 안전 노출 여부 등 안전·물성 정보.
- 기술: REST + JSON, OAuth2 access_token Header 필요.
- 안내: https://udiportal.mfds.go.kr/brd/view/P01_01?ntceSn=38

## 3) C — 보험심사평가원(HIRA)
### 치료재료정보조회서비스
- 공공데이터포털: https://www.data.go.kr/data/3074384/openapi.do
- 제공: 치료재료코드, 품목명, 제조업체명, 수입업체명, 대분류·재료대·중분류코드, **상한단가**, 규격, 급여구분, 단위.
- 빅데이터 포털: http://opendata.hira.or.kr

## 4) B — 거래처 사이트 스크래핑 (PoC 결과)
- 주사기닷컴 익명 GET → **HTTP 403**. 봇 차단 적용됨.
- 다른 거래처도 유사할 가능성 큼. 정상 동작시키려면: 정상 브라우저 UA, 세션 쿠키 유지, 일부는 B2B 로그인 필요, 캡차 우회 우려, 이용약관 검토 필요.
- 비용/리스크: 거래처 사이트 11곳의 셀렉터·로그인 관리 → 유지보수 큼.
- 권장: **C/A로 다 못 채우는 보조 채널**로만. 거래처 사이트 정보가 풍부한 1~2곳 한정 PoC 가치.

## 5) A — 자동 누적 (구현 완료)
- `/api/reconcile` (출고확인서 AI)가 명세서에서 `edi_code / pack_size / pack_unit`도 같이 추출.
- 클라이언트(`sourcing/[id]` applyReconcile)가 매칭된 `product_id` 의 **빈 칸만** 자동 채움(덮어쓰기 없음).
- 사진은 아직 수동(제품 모달의 사진 URL 입력칸). 추후 Supabase Storage 업로드 UI 검토.

## 6) 다음 단계 (제안)
1. 공공데이터포털 회원가입 + API 키 발급(무료, 즉시).
2. `EDI_API_KEY` 환경변수 + 서버 라우트 `/api/catalog/lookup?ediCode=...` 추가.
3. 제품 모달에 "공공 API로 자동 채우기" 버튼 → EDI 코드 기준 조회 → 빈 칸만 보완.
4. (선택) HIRA 치료재료코드 매칭으로 상한단가 참조.
