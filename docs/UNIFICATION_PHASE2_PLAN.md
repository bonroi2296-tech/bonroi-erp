# 주문 ↔ 소싱 일원화: 2단계 계획서

> 결정#3(소싱으로 일원화, 단 220건 보존, 단계적). 1단계는 완료(소싱 품목별 납품가 손수정 + 소싱 완료 → 주문 내역 누적).
> **✅ 2단계 구현 완료(#34).** 아래는 그때 반영한 내용 기록이다. 다음은 §"3단계 미리보기".

## 2단계 목표 (한 줄)
**신규 주문은 "확보 관리(소싱)"에서만 시작**하도록 입구를 통일한다. **"주문 관리"는 기존 220건 보기·수정 전용**으로 역할 축소. 데이터는 단 1건도 안 건드림.

## 변경 범위
1. **사이드바**: "주문 관리" 라벨을 "주문(기존)"으로 변경(혹은 그대로 두되 설명 보조 텍스트로 표시). 위치는 유지.
2. **주문 관리 페이지 상단 안내**: "신규 주문은 **확보 관리**에서 시작하세요. 이 화면은 기존 주문 220건의 조회·수정 전용입니다." 배너.
3. **주문 관리 '신규 주문 등록' 버튼 비활성화/숨김**:
   - 기본은 숨김(없는 듯 깔끔).
   - 부득이 신규를 손으로 넣어야 하는 예외 케이스 대비 "고급 입력(예외용)" 토글로 보존(코드는 그대로, UI에서만 숨김).
4. **대시보드 "주문 만들기" 류 입구가 있으면 → 확보 관리로 리다이렉트** (확인 필요).

## 데이터 영향
- 없음. `orders`/`order_items` 220건 그대로.
- 소싱이 만들어 쌓는 새 주문도 같은 `orders` 테이블이라 주문 내역에서 함께 보임.

## 위험·롤백
- 위험: 사용자가 일시적으로 "신규 주문은 어디서?" 헷갈릴 수 있음 → 배너로 명확히 안내.
- 롤백: "고급 입력" 토글을 켜면 즉시 옛 입구 복구. 코드/라우트는 그대로 보존.

## 체크포인트(반영 결과)
- [x] "주문 관리" 라벨 → **"주문(기존)"** 으로 변경.
- [x] 신규 입력 버튼 → **완전 숨김** (`{false && ...}` 패턴, 코드/로직 보존. 부활은 false→true).
- [x] 안내 배너 → /orders 상단에 "신규 주문은 확보 관리에서 시작, 이 화면은 기존 주문 조회·수정 전용" 표시.

## 3단계 미리보기 (참고)
- 2단계 운영 후 1~2주 안정화 확인.
- 그다음 주문 관리 입력 화면을 메뉴에서도 숨김(코드 보존). 완전 일원화.
- 추후 로그인(결정#1) 도입 시 anon 정책 정리와 함께.
