# Claude로 ERP 개선하기 — 담당자 안내서

> **대상**: 개발을 모르지만 Claude를 시켜서 본로이 ERP를 고치고 개선할 담당자.
> **이 문서만 알면 됩니다.** 코드는 몰라도 됩니다.
>
> - 앱 사용법(화면별) → `docs/USER_GUIDE.md`
> - 시스템 배경·결정사항 → `docs/PROJECT_CONTEXT.md`
> - Claude가 지켜야 할 작업 규칙 → `CLAUDE.md` (담당자는 안 읽어도 됨)

---

## 0. 30초 요약

- 당신은 **"무엇을 바꿀지 정하고 확인하는 사람"**, Claude는 **"코드를 짜는 사람"** 입니다.
- 흐름: **요청 → Claude 작업 → 자동검사 → 저장 → 매일 오후 3시 실제 화면 반영 → 당신이 확인**
- 당신이 실제로 해야 할 일은 3가지뿐입니다.
  1. 원하는 걸 **화면 기준**으로 말하기
  2. Claude가 물어보면 **답하기 / 위험한 건 막기**
  3. 배포된 뒤 **직접 눌러서 확인하기**
- 모르면 그냥 물어보세요. **"이거 쉬운 말로 설명해줘"** 는 언제든 써도 됩니다. 공짜입니다.

## 1. 전체 그림 — 요청이 화면에 반영되기까지

| 단계 | 누가 | 걸리는 시간 | 당신이 할 일 |
|---|---|---|---|
| 1. 요청 | **당신** | 1분 | 채팅창에 원하는 걸 적는다 |
| 2. 작업 | Claude | 보통 몇 분 | 기다린다 (질문 오면 답한다) |
| 3. 자동검사 | Claude | 자동 | 없음 (통과 못 하면 Claude가 알아서 고침) |
| 4. 저장 | Claude | 자동 | 없음 |
| 5. **배포** | 자동 | **매일 오후 3시** | 기다린다 |
| 6. 확인 | **당신** | 5분 | 화면에서 직접 눌러본다 |

### ⚠️ 가장 많이 하는 오해

> "Claude가 다 됐다고 했는데 화면이 그대로예요"

**정상입니다.** 이 프로젝트는 저장한다고 바로 반영되지 않고, **매일 오후 3시(한국시간)에 한 번** 실제 화면에 반영됩니다.
(그 사이엔 코드만 바뀌어 있고 직원들이 쓰는 화면은 어제 그대로입니다.)

급하면 → §7 "지금 당장 반영하고 싶어요"

## 2. 이 단어들만 알면 됩니다

| 개발 용어 | 쉬운 뜻 |
|---|---|
| 저장소 (repo) | ERP 코드가 들어있는 창고 |
| **커밋** | 작업 저장. "이만큼 했다"고 이름 붙여 묶어두는 것 |
| **브랜치** | 원본을 안 건드리고 따로 만든 **작업대(복사본)** |
| **main** | **진짜로 쓰이는 원본.** 여기 들어간 것만 배포됨 |
| **PR** (풀리퀘) | "작업대에서 한 걸 원본에 합쳐도 될까요?" 하는 **결재 요청서** |
| **배포** | 실제 직원들이 쓰는 화면에 반영하는 것 |
| **마이그레이션** | 데이터 창고(DB)의 **서랍 구조 자체**를 바꾸는 것. 되돌리기 어려움 ⚠️ |
| 타입체크 / 린트 / 빌드 | Claude가 스스로 돌리는 **3종 자동검사**. "문법 오류 없음" 확인용 |
| **롤백** | 되돌리기 |
| anon 권한 | 지금 이 ERP는 로그인 없이 씁니다. 그래서 새 서랍(테이블)을 만들 때 **접근 허가를 같이 안 주면 화면이 깨집니다** |

## 3. 요청하는 법 (여기가 제일 중요)

### 좋은 요청 = 4줄 공식

```
어디서 : (화면 이름)
지금   : (지금 어떻게 되어 있는지)
원하는것: (어떻게 되면 좋겠는지)
왜     : (선택. 적으면 Claude가 더 나은 방법을 제안함)
```

### 나쁜 예 vs 좋은 예

| ❌ 이렇게 말하면 | ✅ 이렇게 말하세요 |
|---|---|
| "주문 화면 좀 고쳐줘" | "**주문 내역** 화면에서 거래처별로 색이 다 비슷해서 구분이 안 돼. 거래처마다 확실히 다른 색으로 해줘" |
| "마진 이상해" | "**단가 비교** 화면 마진이 부가세를 뺀 금액으로 나오는 것 같아. 부가세 포함 기준으로 바꿔줘" |
| "빠르게 해줘" | "**확보 관리**에서 거래처 배정을 품목마다 누르는 게 너무 오래 걸려. 여러 개 골라서 한 번에 배정하게 해줘" |

### 💡 실제 있었던 낭비 — "조건은 한 번에 다 말하기"

9월에 마진 표시 하나 고치는 데 요청이 4번 오갔습니다.
(눈에 띄게 → 크기 줄이기 → 입력칸 모양 맞추기 → 부가세 포함으로)

**한 번에 이렇게 말했으면 한 번에 끝났습니다:**

> "단가 비교 화면에 마진을 보여줘. **부가세 포함 기준**으로 계산하고, **다른 입력칸과 같은 모양·크기**로, 너무 크지 않게."

👉 **"완성된 모습"을 먼저 그려서 말하세요.** 한 번 왔다 갔다 할 때마다 배포가 하루씩 밀립니다.

### 그 외 요령

- **사진 붙여넣기 됩니다.** 화면 캡처를 그대로 붙이고 "여기 이 부분"이라고 하면 됩니다. 말로 설명하는 것보다 10배 빠릅니다.
- **한 번에 한 가지.** 단, 그 한 가지에 대한 조건은 전부 한 번에.
- **모르면 물어보세요.** "이렇게 하면 뭐가 안 좋아?", "다른 방법도 있어?", "쉬운 말로 설명해줘"

### 복붙 템플릿

```
[화면] 확보 관리
[지금] 거래처를 품목마다 하나씩 골라야 해서 한 건에 20번씩 클릭해야 함
[원하는것] 여러 품목을 체크해서 한 거래처에 한 번에 배정
[참고] 급하지 않음. 기존 데이터는 절대 건드리지 말고.
```

## 4. Claude 응답 읽는 법 — 5가지 유형과 대답할 말

Claude가 작업하는 중간에 지나가는 파일 이름, 명령어, 코드는 **안 봐도 됩니다.**
**맨 마지막 요약**만 읽으면 됩니다. 그 요약은 보통 아래 5가지 중 하나입니다.

### A. 계획을 제안할 때
> "이렇게 3단계로 하려고 합니다. ① … ② … ③ …"

**대답:** `"그렇게 해줘"` / `"1번만 먼저 해보고 보여줘"` / `"2번은 빼줘"`

### B. 질문할 때 (A안/B안)
> "A는 ~하고 B는 ~합니다. 어느 쪽으로 할까요?"

**반드시 대답해야 진행됩니다.** 판단이 안 서면:

> `"잘 모르겠어. 네가 추천하는 걸로 하고, 왜 그게 나은지 한 줄로 알려줘"`

### C. 다 했다고 보고할 때
확인할 건 딱 3가지입니다.
1. **뭐가 바뀌었나** (화면 기준으로 설명돼 있나)
2. **검사 통과했나** (타입체크·린트·빌드)
3. **내가 확인해야 할 게 뭐라고 하나**

**대답:** `"확인했어"` / `"이 부분은 이렇게 바꿔줘"`

### D. 위험한 작업이라 확인받을 때
> "이 작업은 기존 데이터 ○○건을 수정합니다. 진행할까요?"

👉 **§5로 가세요. 그냥 "응" 하지 마세요.**

### E. 못 했다 / 막혔다고 할 때
> "이건 확인 못 했습니다" / "UI 테스트는 못 했습니다"

**정직한 신호입니다. 좋은 겁니다.** 얼버무리는 것보다 낫습니다.

**대답:** `"그럼 지금 할 수 있는 건 뭐야?"` / `"내가 뭘 확인해주면 돼?"`

---

### 🚨 이 문구가 나오면 뜻을 정확히 아세요

| Claude가 이렇게 말하면 | 진짜 뜻 | 당신이 할 일 |
|---|---|---|
| **"UI 테스트 못 함"** | 화면을 직접 눌러보지 못했다 | **당신이 눌러서 확인해야 함** |
| **"확인 못 함"** | 사실 확인이 안 된 부분 | 추측으로 받아들이지 말 것 |
| **"타입체크·린트·빌드 통과"** | 문법 오류는 없다 | ⚠️ **숫자가 맞다는 뜻이 아님.** 계산은 따로 확인 |
| **"마이그레이션 적용 완료"** | **실제 DB가 이미 바뀌었다** | 되돌리기 어려움. 숫자 확인 필수 |
| **"~것 같습니다 / ~로 보입니다"** | 확신이 없다 | "확실해? 어떻게 확인했어?" 라고 되물을 것 |

## 5. 반드시 멈추고 대표(PO)에게 물어볼 것

### 🔴 혼자 승인하지 말 것

| 상황 | 예시 |
|---|---|
| **기존 데이터를 고치거나 지움** | 중복 제품 합치기, 단가 일괄 수정, 주문 내역 정정 |
| **돈 계산 규칙 변경** | 마진 기준, 부가세, 청구액, 납품가 계산식 |
| **로그인·권한 관련** | 로그인 켜기, 접근 권한 변경 |
| **화면·메뉴 없애기** | 쓰던 화면 삭제 |
| **"한 번에 갈아엎자"는 제안** | 구조 통합, 대규모 리팩터링 |

이럴 땐 이렇게 답하세요:

> `"잠깐. 이건 대표님 확인받고 할게. 무엇이 어떻게 바뀌는지, 잘못되면 되돌릴 수 있는지 3줄로 정리해줘."`

### 🟢 그냥 진행해도 되는 것

글자·색·크기·정렬, 표 모양, 버튼 위치, 안내 문구, 필터·검색 추가, 오타 수정, 정렬 순서
→ 잘못돼도 다시 말하면 바로 되돌아갑니다.

## 6. 배포된 뒤 확인 체크리스트

**오후 3시 이후에** 하세요.

- [ ] 화면 강제 새로고침 (`Ctrl + Shift + R`)
- [ ] 바꿔달라고 한 화면을 **직접 눌러본다**
- [ ] 숫자를 바꿨다면 → **실제 건 1개를 손으로 계산해서 대조** (특히 마진·부가세·단가)
- [ ] **안 건드린 화면도 하나 확인** (주문 내역, 대시보드)
- [ ] 이상하면 즉시:
      `"방금 배포된 거 문제 있어. [무슨 화면]에서 [무슨 일]이 생겨. 되돌려줘."`

## 7. 자주 있는 상황

### "화면이 안 바뀌었어요"
1. 오후 3시 지났나? → 안 지났으면 **정상**
2. 지났으면 `Ctrl + Shift + R`
3. 그래도 그대로면 → `"배포됐는지 확인해줘"`

### "지금 당장 반영하고 싶어요"
- Claude에게: `"지금 바로 배포해줘"`
- 직접 하려면: GitHub → 저장소 → **Actions** 탭 → 왼쪽 **"매일 오후 3시 배포"** → **Run workflow** 버튼
- 반영까지 보통 몇 분 걸립니다.

### "숫자가 이상해요"
**반드시 실제 사례 1건을 같이 주세요.** 그래야 원인을 찾습니다.

```
주문 내역에서 9/8 A병원 주사기 건, 마진이 -3,000원으로 나오는데
매입 10,000 / 납품 12,000 이라 +2,000이 맞아. 주문번호는 ○○○.
```

### "에러가 떴어요 / 화면이 하얘요"
스크린샷 + **"무엇을 누르다가 그랬는지"** 를 같이 주세요.

### "직원들이 개선 요청 버튼으로 보낸 걸 보고 싶어요"
화면 우하단 파란 **개선 요청** 버튼으로 들어온 내용은 DB에 쌓입니다.

> `"개선 요청(feedback)으로 들어온 것들 정리해서 보여줘. 비슷한 것끼리 묶고 뭘 먼저 하면 좋을지 추천해줘."`

### "대화가 너무 길어졌어요 / 느려졌어요"
새 대화를 시작하고 §8 첫 마디를 붙여넣으세요. 이전 대화 내용은 이어지지 않지만, 문서를 읽고 따라잡습니다.

### "Claude가 엉뚱한 걸 하고 있어요"
바로 멈추고:

> `"잠깐 멈춰. 그건 내가 원한 게 아니야. 내가 원한 건 ○○○ 이야. 지금까지 한 거 되돌리고 다시 하자."`

## 9. 복붙용 문장 모음

**요청할 때**
- `[화면] / [지금] / [원하는것] 형식으로 정리했어. ~~~`
- `이거 하면 다른 화면에 영향 가는 거 있어? 있으면 먼저 알려줘.`
- `기존 데이터는 절대 건드리지 말고 화면만 바꿔줘.`

**이해가 안 될 때**
- `방금 설명 쉬운 말로 다시 해줘. 화면에서 뭐가 어떻게 달라지는지로.`
- `이거 잘못되면 어떻게 되돌려?`
- `A랑 B 중에 뭐가 나아? 장단점 한 줄씩만.`

**멈추게 할 때**
- `잠깐. 대표님 확인 먼저 받을게. 진행하지 마.`
- `이건 위험해 보여. 안 하는 걸로 하고 다른 방법 찾아줘.`

**확인할 때**
- `방금 한 작업 요약해줘. 뭐가 바뀌었고 내가 화면에서 뭘 확인하면 돼?`
- `검사 다 통과했어? 내가 직접 봐야 하는 건 뭐야?`
- `배포됐어? 언제 화면에 보여?`

**되돌릴 때**
- `방금 바꾼 거 되돌려줘. [무슨 문제]가 생겼어.`

## 11. 인수인계 메모 (지금 상태)

- **로그인 없이** 쓰는 구조입니다. 그래서 새 DB 서랍(테이블)을 만들면 **접근 권한을 같이 줘야** 화면이 안 깨집니다. Claude가 알아서 하지만, DB를 건드렸다고 하면 한 번 물어보면 좋습니다: `"anon 권한도 같이 줬어?"`
- **진짜 데이터는 라이브 DB에 있습니다.** 코드에 적힌 설명보다 실제 DB가 우선입니다.
- 요즘은 작은 화면 수정을 **main에 바로 저장**하고 있습니다. 화면만 손보는 건 그래도 괜찮지만,
  **DB·데이터·돈 계산을 건드리는 작업은 PR(결재 요청서)로 남겨달라고 하세요.**
  → `"이건 바로 main에 넣지 말고 PR로 만들어줘. 대표님이 보고 결정할 거야."`
- 배포는 **매일 오후 3시 자동 1회**. 그 사이 저장된 것들이 한꺼번에 나갑니다.
